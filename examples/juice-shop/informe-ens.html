No conformidades

Medidas con veredicto «No cumple» o «Parcial». Requieren acción correctora.

  • op.pl.1 Análisis de riesgos

    A STRIDE threat model exists with owner and data-flow diagrams (assets/threats), which partially addresses asset/threat identification, but there is no formal ENS risk analysis mapping safeguards and residual risks.

  • op.pl.2 Arquitectura de seguridad

    Some architecture documentation and network segmentation exist (VPC/subnets/security groups/ALB in Terraform, threat-model data-flow diagrams), but there is no ENS security architecture doc with lines-of-defence, interconnection points or authentication scheme description.

  • op.pl.3 Adquisición de nuevos componentes

    Automated dependency updates and locked dependencies exist, giving some procurement/component control, but no process ties component acquisition to risk-analysis conclusions, security architecture, training or funding.

  • op.pl.4 Dimensionamiento / gestión de la capacidad

    Resource sizing is defined (ECS task CPU/memory, desired count, compose memory limits, subnet layout), partially covering processing/storage capacity, but no formal capacity-management analysis across personnel/communications/facilities dimensions.

  • op.pl.5 Componentes certificados

    No evidence of selecting CCN-CPSTIC-qualified/certified products or Article 19-certified components. The stack uses standard upstream images (nginx/redis/mongo) and npm packages with no certification reference.

  • op.acc.1 Identificación

    Accounts have unique identifiers (UserModel id/email) and distinct roles (customer/deluxe/accounting/admin), partially satisfying identification, but there is no ENS-grade identity management, account-disable lifecycle or retention period.

  • op.acc.2 Requisitos de acceso

    Access-control enforcement is intentionally broken: CORS allows everything, an authorization middleware on product modification is commented out, and directory/file listing is exposed. Access to resources is not reliably restricted to authorised entities.

  • op.acc.4 Proceso de gestión de derechos de acceso

    Roles exist but least-privilege and periodic access review are not implemented; privilege escalation and broken access control are intentional challenges, and some destructive endpoints deny all while others are deliberately left open.

  • op.acc.5 Mecanismo de autenticación (usuarios externos)

    External authentication is intentionally weak: login uses string-concatenated SQL, a default weak admin credential (admin123) is a known challenge, and rate limiting is applied only to reset-password, not login (no attempt limiting/lockout).

  • op.acc.6 Mecanismo de autenticación (usuarios de la organización)

    Organisation-user authentication lacks credential lifecycle controls: weak/default passwords are intentional challenges, no rotation policy exists, and lockout/attempt-limiting for internal users is absent.

  • op.exp.1 Inventario de activos

    A CycloneDX SBOM is generated at build time, partially covering a software-component inventory, but there is no complete asset inventory identifying every system element and its responsible owner.

  • op.exp.2 Configuración de seguridad

  • op.exp.3 Gestión de la configuración de seguridad

    Security-relevant configuration is version-controlled and schema-validated, giving partial configuration management, but there is no controlled change/authorisation process for security configuration nor guarantee of minimum-functionality/least-privilege.

  • op.exp.4 Mantenimiento y actualizaciones de seguridad

  • op.exp.5 Gestión de cambios

    Change control exists via PR/branch model and CI checks (lint, tests), but there is no formal change-request registry, pre-production equivalence testing record, or risk-based approval by a Security Officer.

  • op.exp.6 Protección frente a código dañino

  • op.exp.7 Gestión de incidentes

    A vulnerability-reporting policy and CSAF advisory feed exist (partial incident/weakness handling), but there is no integral incident-management process with classification and notification escalation.

  • op.exp.8 Registro de la actividad

  • op.exp.9 Registro de la gestión de incidentes

    CSAF security advisories are recorded, giving partial incident/vulnerability record keeping, but there is no register of initial/intermediate/final incident reports or legally-admissible evidence handling.

  • op.exp.10 Protección de claves criptográficas

  • op.ext.3 Protección de la cadena de suministro

    Supply-chain hygiene partially exists (Dependabot, CodeQL, SBOM generation), but there is no analysis of supply-chain incident impact, risk estimation or containment measures.

  • op.nub.1 Protección de servicios en la nube

    The system is deployable on AWS (public cloud, IaaS) via Terraform, but there is no evidence of CCN-STIC service-model conformity, pentesting, transparency, key management or data-jurisdiction requirements.

  • op.cont.4 Medios alternativos

    Technical redundancy exists (2 ECS tasks, two AZ subnets, restart policies, transitive EFS encryption), partially covering alternate means, but there is no planned alternate facilities/personnel/communications or maximum activation time.

  • op.mon.1 Detección de intrusión

    No intrusion detection/prevention tools are deployed. Network configuration defines only security groups and an ALB; there is no WAF/IDS/IPS or equivalent detection mechanism.

  • op.mon.2 Sistema de métricas

    A Prometheus metrics endpoint and a Grafana dashboard exist, giving partial measurement, but they track application/business metrics, not ENS measure-implantation metrics or the annual report required by art. 32.

  • op.mon.3 Vigilancia

    Automatic event collection partially exists via morgan access logs (daily rotation, audit.json), but there is no SIEM/correlation or security-event surveillance system.

  • mp.com.1 Perímetro seguro

  • mp.com.2 Protección de la confidencialidad

  • mp.com.3 Protección de la integridad y de la autenticidad

  • mp.com.4 Separación de flujos de información en la red

    Internal services are placed on a dedicated bridge network and redis/mongo are only exposed internally (not published to the host), partially separating information flows, but there is no evidence of traffic segregation or wireless segmentation policy.

  • mp.si.2 Criptografía

  • mp.sw.1 Desarrollo de aplicaciones

  • mp.sw.2 Aceptación y puesta en servicio

    Extensive automated test suites (unit/integration/e2e/smoke) provide partial acceptance testing, but no explicit security acceptance criteria or non-deterioration checks for other components are documented.

  • mp.info.1 Datos personales

    The system processes personal data and exposes data-export/erasure request endpoints, partially covering data-subject rights, but there is no documented RGPD/DPD requirement set or impact assessment.

  • mp.info.2 Calificación de la información

    No information classification levels, USO OFICIAL marking, information-owner assignment or criteria for required security level exist. Configuration and data models treat all information uniformly (no classification field).

  • mp.info.6 Copias de seguridad

  • mp.s.2 Protección de servicios y aplicaciones web

    The web application is intentionally vulnerable: XSS protection is disabled, SQL injection is intentional, and injection/XSS/broken-access challenges are part of the design, so the web-service protection requirements are demonstrably not met.
